# Native recording module installation

The installer owns only `admin/modules/myteldeskrecording/{module.xml,functions.inc.php}` beneath the configured native administration directory. The module uses Issabel's generated-dialplan hook and does not replace native macros, edit vendor PHP, change global Dial options or restart Asterisk. Recording and native policy behavior remain defined by the generation module and recording renderer.

Registration calls the supported native module API for one fixed module. It deliberately avoids the command-line wrapper's root-only global permission reset. Native return values must be boolean `true`, with strict version/enabled/absence and pending-state readback. Configuration generation uses the existing strict native Apply adapter. Doctor checks installed ownership and actual loaded recording call paths, rather than only finding the unused legacy hook body.

Existing directories or database registration without installer ownership are refused, even when their contents look familiar. The private installer state records module hashes and intent before changes. Configuration files use the existing private transaction journal. Upgrade, rollback and uninstall affect only the owned module; unrelated identities, credentials, recording data and native recording policy are retained. Unknown edits or partial state stop for scoped recovery.

An unstarted transaction is distinct from one that has written files or registered the module. Refusal before the mutation boundary, including newly pending operator settings, must not stop the service or run native Apply. Recovery of an untouched intent similarly restores only installer bookkeeping. Native administration paths and parent identities are rechecked before writes and lifecycle operations; these checks do not claim to isolate a compromised native PBX administrator or provide a general concurrent-filesystem transaction.

The test-first checkpoints include the missing lifecycle adapter/helper, missing activation and rollback orchestration, preflight-to-write directory/registration drift, ready-install removal, and unchanged operator pending state. The inert PHP fixture tests non-boolean native return values, failed/duplicate metadata, version/enabled mismatches, fixed-module scope and native working-directory behavior without loading PBX configuration or connecting to a database. Python fixtures exercise real temporary files with fake commands, including recovery and owned upgrade rollback.

Native service installation, generated-dialplan acceptance, real calls, recording files and VAD remain separate integration gates. Passing lifecycle or PHP boundary tests does not establish those outcomes. Supported Asterisk versions do not by themselves establish compatibility with every distribution's dialplan generator; unsupported generation structure is refused rather than silently treated as working.
